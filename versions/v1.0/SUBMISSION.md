## B. 项目详情（6 个必填文案字段）

### 项目背景
```
大学生和职场新人每天面对大量琐事、临时灵感和长周期项目（期末复习、毕设、论文等），
但现有工具（滴答清单、Notion、微软 Todo）有三个共性短板：
1）临时蹦出来的琐事要"建项目-分类-填时间"，录入成本高；
2）长周期目标（"准备期末考试"）需要人工拆解成子任务；
3）工具不记得用户的偏好（"复习类任务别拆太碎"），每次都要重新调。

这是一个没人解决的"小麻烦"，却几乎影响着每个学习/工作场景的效率。
```

### 解决的问题
```
1. 临时琐事/灵感快速收集：单输入框+回车即入库，无需分类
2. 长周期项目智能拆解：输入目标 → AI 自动拆为子任务（5-12 条）
3. 智能重排：基于截止日期、优先级、用户偏好自动重排
4. 反馈记忆闭环：👎 反馈 → 偏好沉淀 → 下次显式应用"已应用你的偏好"
5. 一键分享：5 秒生成可分享链接，跨设备同步，零账号零后端
```

### 核心功能
```
1. 双模式：琐事快速收集 / 项目智能拆解重排（侧栏一键切换）
2. 智能输入框：文本 / 图片（视觉识别）/ 语音三种入口
3. 项目拆解：AI 拆为子任务，预览可编辑后批量入库
4. 智能重排：基于截止时间、优先级、偏好的打分排序
5. 反馈记忆系统：👍/👎 反馈 → 关键词抽取偏好 → localStorage 沉淀 → 显式应用
6. 记忆日志面板：所有偏好和应用记录可视化、可启停/删除
7. 模拟/真实 API 双通道：不填 Key 也能用，真接 DeepSeek 后功能完整
8. 分享/导出：URL LZString 压缩分享 + JSON 文件备份
9. 拖拽排序：HTML5 原生拖拽，跨列移动
10. 加载演示数据：一键进入最佳演示状态
```

### 技术方案
```
单文件 SPA（一个 index.html，约 1800 行）：
- HTML + 原生 JavaScript（无 React/Vue，零构建）
- Tailwind CSS（CDN 运行时版）+ FontAwesome 6 + LZString（CDN）
- localStorage 持久化所有数据

AI 接口（OpenAI 兼容 Chat Completions）：
- 文本模型：deepseek-chat
- 视觉模型：deepseek-v4-flash-vision-exp（2026-08-21 上线，单图 ≤384 tokens）

记忆系统：
- 关键词 + 规则引擎抽取偏好（granularity / priorityStyle / density）
- 权重机制（0-1，≥0.5 注入 prompt）
- 显式横幅高亮"已应用你的偏好"

5 级错误兜底（演示不翻车）：
1. 网络失败/超时 → 重试 1 次 → 走本地规则
2. 401 → 切回模拟模式
3. 429/余额不足 → 切回模拟
4. 返回非 JSON → 强解析 → 本地规则
5. 永不抛错导致白屏
```

### 创新点
```
1. 反馈记忆的"沉淀-检索-应用"完整闭环：用户反馈后真的"被记住"，下次真的"被应用"
2. 偏好显式高亮：UI 顶部横幅直接显示"已应用你的偏好：拆解更细（来自 3 次反馈）"，
   解决"AI 黑盒"信任问题，让用户看见 AI 在为他调整
3. 模拟+真实双通道：演示不翻车，生产可上线，零成本体验
4. 单文件零后端：双击 index.html 即可跑，5 秒分享链接跨设备传播
5. 偏好权重衰减机制：随反馈次数自然积累，可手动停用/删除
```

### 应用价值
```
真实场景：
- 期末/毕设/论文等长周期任务的拆解 + 跟踪 + 智能重排
- 杂事/灵感/临时待办的快速收集与智能归类
- 偏好被记住后越用越顺手，真正"走进真实场景"

传播方式：
- 单文件：双击即用，零门槛
- 分享链接：5 秒跨设备，零账号
- JSON 导出/导入：用户可备份可迁移
- GitHub 公开仓库：评委可看完整代码和 commit 证据链

赛道 1（真实问题 + 走进真实场景） + 赛道 4（反馈记忆）双命中。
```

## C. 使用说明

```
1. 双击 index.html 在浏览器打开（或访问在线演示链接）
2. 顶栏 ⚙ 设置 → 加载演示数据 → 体验完整场景
3. 切换「琐事/项目」模式：侧栏点击对应导航
4. 智能输入：文本/📷图片/🎤语音 三种入口，回车解析为任务
5. 任务反馈：鼠标悬停任务卡 → 点 👎 选原因 → 偏好被记录
6. 智能拆解：项目模式 → 点「✨ 智能拆解」→ 预览后确认入库
7. 智能重排：项目模式 → 点「🔄 智能重排」→ 顺序变化+理由
8. 记忆面板：侧栏底部「🧠 记忆」→ 查看所有偏好和日志
9. 分享：顶栏「🔗 分享」→ 链接自动复制
10. 接入真 API：设置 → 填 DeepSeek Key → 切"真实"模式
```

## H. GitHub 仓库 5 步走（零基础详细版）

### Step 1 · 注册 GitHub
- 访问 https://github.com
- Sign up，用你的邮箱
- **用户名取好**（会出现在公开链接）：比如 `wxy-zsh`、`xiaowang-flowmate`
- 选 Free 套餐

### Step 2 · 创建仓库
- 登录后右上角 `+` → `New repository`
- 填表：
  - Repository name: `flowmate`
  - Description: `轻量个人事项 Agent，具备反馈记忆能力`
  - **Public**（必选，公开可访问）
  - 勾选 `Add a README file`
  - Add license: `MIT`
- 点 `Create repository`

### Step 3 · 上传代码
- 进仓库页面 → 点 `Add file` → `Upload files`
- 把本地的 `index.html` 拖到上传区
- 下方填 commit message：`feat: 初始化 FlowMate v1.0 单文件 SPA`
- 点 `Commit changes`
- **再上传 README.md**（如果 GitHub 自动生成的 README 还在，可以点击它修改，或者覆盖上传）
- 同样方法上传 LICENSE 文件

### Step 4 · 启用 GitHub Pages（在线演示）
- 仓库 → Settings → Pages
- Source 选 `Deploy from a branch`
- Branch 选 `main` / `(root)`
- 几分钟后会出现链接：`https://你的用户名.github.io/flowmate/`

### Step 5 · 拿到链接
- 仓库主页：复制浏览器地址栏 URL，就是代码仓库链接
- 格式：`https://github.com/你的用户名/flowmate`
- 填到提交表单的"代码仓库"字段
- GitHub Pages 链接填到"在线演示"字段
